# Changelog

## 1.1.1 — 2026-10-20

- **Messages at the top of the page:** order rule messages are shown after the WooCommerce notices at the top of the classic cart and checkout pages (`.ccfo-order-notices`, `woocommerce-info`), not next to the buttons. The refreshed parts of the page carry the current messages as data and `build/order-notices.js` keeps the top up to date (checkout refresh, cart update, shipping change); new messages are scrolled into view. The mini cart shows its short message above the disabled button.
- **Rule editor:** checkout fields and product categories are chosen in two steps (kind of condition, then the field or category); stored rules are unchanged. The server explains a missing second step ("Choose a checkout field." / "Choose a product category.").
- **Rule editor:** search lists float over the form instead of pushing it down and show more entries; the value input has no visible label or how-to text, so condition rows line up; "Rule name" and "Priority" start on the same line; range inputs use Min/Max placeholders.
- Block themes (Twenty Twenty-Five): the disabled cart and mini cart buttons get the theme's button class (`wc_wp_theme_get_element_class_name()`), like WooCommerce's own buttons; they were unstyled before.
- Tests: unit 134, integration 112, Jest 109; full E2E 41/41 on Woodmart and on Twenty Twenty-Five (E2E notice and Cart Block selectors no longer depend on the theme). WordPress.org screenshots taken on Twenty Twenty-Five.

## 1.1.0 — 2026-10-20

Order rules and amount conditions (SPEC §13).

- **Order rules** (new target `order`): `block_checkout` holds back "Proceed to checkout" (classic cart, mini cart, Cart Block) and "Place order"; `block_order` holds back "Place order" only. Messages per rule with `{min}`, `{max}`, `{remaining}`, `{excess}`, `{current}`; a default message in Settings. The classic checkout refuses the order in `woocommerce_after_checkout_validation`, the Store API with `ccfo_order_blocked` (400). Express payment buttons are not shown while the order is blocked.
- **New condition sources:** `cart.subtotal_incl_tax`, `cart.contents_total`, `cart.discount_total`, `cart.shipping_total`, `cart.tax_total`, `cart.max_item_price`, `cart.min_item_price`, `cart.coupons` and `cart.category_subtotal:<term id>` (sub-categories included, variations by their parent). Every existing source can be used in order rules.
- **Linter:** order rules without conditions, condition groups whose number conditions contradict each other (checked for every rule), unknown or empty placeholders, deleted categories; condition fields that no longer exist are now also reported for tax and order rules.
- **Checkout Block:** order rules that read the payment method update at once from per-method messages (`orderBlockedByMethod`), without a server round trip. Tax rules that read the payment method: with nothing chosen yet the server assumes the first available method, as the block does, so nothing is sent while the page loads; a change is sent after a 3.5 s pause in address input. The cart response used to overwrite address input WooCommerce had not sent yet (found by E2E; the test fails 3/3 without the pause).
- **Store API:** field and order checks run only when the order is placed (`POST`), not for draft updates (PUT/PATCH).
- Tests: unit `OrderRulesTest`, `MessagesTest` (brute-force check of contradicting groups); integration `AmountSourcesTest`, `OrderRestrictionsTest` (incl. a real Store API checkout); Jest `order-guard.test.js`; E2E `order.spec.js` (classic cart/checkout, Cart Block, Checkout Block, admin). Fixtures add a Cart Block page.

## 1.0.0 — 2026-10-18

First public release on WordPress.org.

- WordPress.org readiness: readme with screenshots, privacy and source code sections; direct-access guard in every PHP file; Plugin Check 2.1.0 (including experimental checks) reports no errors or warnings; human-readable JS sources and build config shipped in the zip; plugin URI and author updated.
- WordPress.org assets in `.wordpress-org/` (icon, banners, six screenshots), generated by `tools/wporg-assets.js` and `tools/wporg-screenshots.js`.
- GitHub Actions: tag `x.y.z` deploys to WordPress.org SVN and attaches the zip to a GitHub release; readme and asset changes on `main` update WordPress.org. Both stay off until the repository variable `WPORG_ENABLED` is `true`.

- Admin: Checkout Block fields added with `woocommerce_register_additional_checkout_field()` are listed as managed by their own plugin (SPEC 2.5).
- Number conditions (cart subtotal, total, quantity, weight) no longer offer "is empty" / "is not empty", as in SPEC §5; these values are never empty.
- Translation template updated with the 0.1.1 strings.
- E2E: `npm run test:e2e:smoke` runs a representative set of 21 browser tests (tag `@smoke`) covering every target type, every action family, each kind of condition source, the classic checkout, the Checkout Block and the admin screen.
- GitHub: README, CONTRIBUTING, SECURITY, LICENSE (GPL-2.0), issue and pull request templates. LICENSE is included in the zip.
- Tests: exhaustive PHP/JS parity matrix (4,290 operator cases, 504 action combinations, 2,955 AND/OR shapes) with a SPEC oracle, all 2,530 target × source × operator combinations of the schema, every source in every request mode, every target × action through WooCommerce hooks, server refusals, REST API, settings, uninstall, classic runtime in a DOM.

## 0.1.1 — 2026-10-18

- Fix: payment, shipping and tax rules that read a checkout field (for example "offer BACS when the company name is filled in") now work for guests and for values typed during checkout. The classic checkout script was only loaded for field rules, so WooCommerce never refreshed the payment list when such a field changed; it only worked when the value was already saved in the customer profile.
- The classic checkout refreshes only when the result of such a condition changes: right away when the customer leaves the field, and at the latest after the "Live update delay" (default 5 seconds) while they are still typing.
- New setting: WooCommerce → Checkout Rules → Settings → Live update delay (0–30 seconds). The "Customer messages" tab is now "Settings".
- Fix: product conditions in the admin showed ids instead of names, and choosing a product from the search saved an invalid value. The server now also rejects product/term conditions that are not ids.
- Fix: product labels no longer repeat the id.

## 0.1.0 — 2026-10-17

First release.

- Rule engine with groups (AND/OR), 23 operators, priorities and conflict policy; PHP and JS evaluators share one test fixture set.
- Classic checkout: show/hide/require for any registered field, live in the browser and checked again on submit; hidden values are not stored.
- Payment and shipping method rules for the classic checkout and the Checkout Block (Store API), including a shipping rate cache key so cached rates never bypass rules.
- Tax rules: hide the "includes tax" note, VAT exemption, switch to an existing tax class.
- Checkout Block: `require` rules enforced on order placement, payment method sync for rules that read it.
- Admin screen (WooCommerce → Checkout Rules): rule editor, live checks for conflicts and rules that remove every method, import/export, customer messages, notice when rules blocked a checkout.
- Applied rules stored on the order (`_ccfo_applied_rules`, HPOS compatible).
